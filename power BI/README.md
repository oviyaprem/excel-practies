Data Import & Query Setup: Imported List of Orders, Order Details, and Sales Target into the Power Query Editor so all data cleansing and structural changes occur reproducibly before loading into the data model.                                                                      
Row Limiting & Data Type Standardization: Restricted List of Orders to the first 500 records to define the working dataset scope. Standardized Order Date to a unified Date format or accurate chronological analysis, and converted Amount and Target to Fixed Decimal Number to maintain financial precision.                                                                                                      
Text Formatting: Applied trimming and Proper Case (Capitalize Each Word) to CustomerName to eliminate trailing spaces and ensure uniform text capitalization across customer records.             
Feature Engineering (Column Creation): Combined City and State into a single Location column (City, State) to streamline geographic reporting. Created a calculated Profit Margin column (Profit / Amount, formatted as a percentage) to evaluate relative product profitability alongside raw revenue. 
Conditional Classification: Added a Profit Status conditional column categorizing every transaction into Loss(Profit < 0), Break-Even (Profit = 0), or Profit (Profit > 0) for rapid performance segmentation. 
Table Merging (Joins): Merged List of Orders and Order Details on Order ID into a consolidated Orders Data table, combining customer/location attributes with line-item sales and profit metrics in a single flat table for reporting. 
Missing Data & Duplicate Handling: Audited column quality across all tables to remove empty/null key records and eliminate duplicate Order ID entries in List of Orders, preventing double-counting while preserving valid multi-item lines in Order Details. 
Sorting & Filtering: Sorted Orders Data by Order Date in descending order to prioritize recent transactions and applied state-level filtering (e.g., Tamil Nadu) to isolate regional sales performance. 
Data Aggregation (Grouping): Duplicated Order Details to summarize distinct Order ID counts, average Profit, and total Amount by Category and Sub-Category. Duplicated Sales Target to aggregate total Targetvalues by Month of Order Date for monthly goal tracking. 
Relational Data Modeling: Established active relationships in Model View linking List of Orders to Order Details via Order ID (one-to-many, as each order contains one or more product items) and Order Details to Sales Target via Category, enabling cross-table filtering between actual sales and category targets.
